# Mobile offline startup and playback

Version 1.15 checks for application updates at entry. Resuming the activity or watching for 15 minutes does not run another check or replace playback with an update screen. Without validated Internet, entry defers a known pending update and keeps its manifest, resumable download and installation records for the next online entry. Losing connectivity during an update download also opens the app without discarding that download. APK verification still completes before installation; malformed metadata, TLS errors and invalid APKs are not accepted as updates.

Version 1.16 separates verified membership/device authorization from online screen reservation. Membership is saved immediately after verification, before acquiring a concurrent streaming screen. A full allocation of online screens cannot revoke valid offline downloaded playback. The checkpoint retains the account, installation, full subscription metadata and original expiry and is excluded from backup.

Existing 1.14/1.15 installations without that checkpoint can recover it from their committed Firestore subscription cache. Mobile/Basic additionally need a committed device binding matching this installation. Pending writes, missing/unknown plans, another account/device and expired or revoked membership cannot create access. A newer committed subscription takes precedence over an older checkpoint. Confirmed denials/sign-out leave persistent revocation markers; stale cache cannot clear those markers, while fresh successful server verification can. Transport failures do not downgrade the saved paid account, and the original expiry and existing renewal-grace rules still apply.

With neither a usable checkpoint nor committed entitlement cache, authenticated offline entry still opens the local library for inspection/deletion without changing saved subscription details or deleting downloads. Playback requests verification rather than granting a plan or opening checkout solely because the network is unavailable. Completed downloads remain authorized by verified local membership; access to the app UI is independent of that entitlement.

Version 1.17 background downloads save the same durable membership checkpoint after their fresh server/device verification, before starting or resuming media transfer. They use the verified transaction result for both download-plan limits and the checkpoint, rather than combining a new subscription read with an older in-memory device confirmation. Entry and workers share a store and write generation: a delayed worker cannot overwrite a newer verified plan or remove a newer sign-out/revocation marker. A storage failure stops the new transfer without treating the paid membership as revoked. The original expiry, account, installation and payment details are preserved; offline downloads do not extend a subscription or reserve a streaming screen.

Legacy download database rows and media files contain no independently verified subscription license. When both the verified checkpoint and committed membership cache are genuinely absent, there is no reliable local account/expiry/device evidence to recover. That installation must reconnect once for fresh verification before those files can play. The checkpoint written by future background downloads prevents that specific omission, but cannot recreate deleted entitlement data or authorize files for another account.

Restored offline access does not reserve a server streaming slot. On reconnection, the background app session refreshes membership/device authorization and acquires a screen before enabling a new remote stream. The player uses local admitted state and does not start membership transactions. A transport interruption to an already admitted session does not turn its paid membership into Guest.

Startup loads the saved catalog and profiles. Offline entry makes cache-only membership reads and never waits on Firestore transactions, a remote catalog or its full-screen loading overlay. Reconnect admission uses bounded retry delays. Clips requires online admission and verified Premium membership, and games require verified membership; saved plan display fields alone cannot authorize paid features. Reconnected subscription updates include account/generation ownership and are applied atomically with session invalidation.

Regression coverage includes offline entry with and without a pending upgrade, preserved download/install records, connection loss during a paused update download, online enforcement of retained upgrades, checkpoint recreation after process restart, legacy committed-cache migration, pending/missing cache, full subscription metadata round trips, account/device mismatch, expiry/revocation, stale tiers and concurrent account changes, online screen limits, library playback dispatch without an incorrect purchase prompt, blocked Clips, and a connection dropping during catalog preparation. Background checkpoint tests also cover fresh verification before media transfer, delayed worker success/failure against a newer plan or revocation, account switches, cancellation and disk-write failure. Physical-device playback is not exercised by these headless tests.
